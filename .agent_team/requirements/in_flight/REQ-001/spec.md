# 特性切片需求：REQ-001 地图足迹大盘与地理标记 (Geo-Footprint Dashboard & Tagging)

## 1. 业务价值与所属领域
- **所属领域**：`domain_tree/management/`（管理后台）与 `domain_tree/storage/`（存储元数据）
- **核心目标**：为 Cloudflare Pages + Telegram 存储的开源图床系统引入“时空足迹（Time & Space）”探索能力。解决传统相册仅能按文件名或单一时间线浏览的痛点，通过前端轻量 EXIF 自动嗅探与可视化地图选点打卡，在后台提供按目录/多标签筛选的在线地图足迹大盘，并支持为照片沉淀短留念与长篇旅行图文故事。

---

## 2. 演化路线图 (Roadmap)
* **Phase 1 (本次 MVP)**: 图片前端极速 EXIF 嗅探 + 可视化地图选点器 + 前端辅助逆地理编码 + 单图文故事（短留念+长游记） + 基础足迹大盘（点聚合 + 目录/多标签筛选 + 右侧滑出照片抽屉）。
* **Phase 2 (后续迭代)**: 自定义多大盘管理（“我的全量足迹”、“和朋友A的足迹”多画板管理与照片/目录归集） + 视频切片 GPS 嗅探 (`Blob.slice` 异步嗅探，超时 300ms 自动降级选点) + 时间轴滑动器 (Timeline Slider)。
* **Phase 3 (进阶扩展)**: 大盘只读加密外链分享 + 轨迹连线与路线回放 (GPX) + 足迹海报生成。

---

## 3. 本次 MVP 范围收敛 (In Scope vs. Out of Scope)

### 3.1 本次范围 (In Scope)
1. **D1 数据架构扩展**：
   - 扩展 `files` 表存储字段：纬度 `latitude` (REAL)、经度 `longitude` (REAL)、地点名称 `location_name` (TEXT)、图文故事 `description` (TEXT)。
2. **前端图片极速 EXIF 嗅探（上传无感）**：
   - 在用户选择图片文件（JPEG/HEIC/WebP）后，前端通过浏览器原生 `FileReader` 仅切片读取文件头部 EXIF 信息。
   - 解析耗时控制在 **< 5ms**，在用户点击上传前或上传瞬间完成坐标抓取并随表单提交，对上传带宽与效率零影响。
3. **管理后台可视化地图选点器（彻底告别手输经纬度）**：
   - 后台照片详情/编辑弹窗内置轻量交互地图选点控件。
   - **点哪标哪**：用户点击地图任意位置即自动落图钉并抓取坐标；支持拖拽图钉微调，支持一键清除定位。
4. **前端辅助逆地理编码（自动推测地名）**：
   - 图钉落下后，前端异步调用免费公开逆地理服务（如 OpenStreetMap Nominatim），自动推测并填充地名至「地点名称」输入框。
   - 允许用户手动修改/覆盖推荐地名（如自定义为“我与小红吃火锅的地方”）。
5. **照片故事与文字记录（短留念 + 长游记双兼容）**：
   - 支持简短的一行留念，也支持多行长篇旅行游记故事排版。
6. **基础足迹大盘页面（全屏地图 + 标签/目录过滤）**：
   - 后台「🗺️ 足迹大盘」专属页面入口。
   - **点聚合（MarkerCluster）**：自动聚合成数字气泡，解决成百上千密集点位卡顿。
   - **空数据过滤**：无 GPS 的照片自动排除，不在地图上产生脏数据。
   - **联动筛选器**：
     - 支持按相册目录（`directory`）单选/多选过滤；
     - 支持按标签（`tags`）多选过滤（支持单张照片多标签检索）。
   - **联动展示**：点击标记点/聚合点，右侧滑出抽屉（Drawer）展示当前位置的照片瀑布流、地名、拍摄时间与文字故事。

### 3.2 明确排除 (Out of Scope - 强制必填)
1. **历史存量照片批量迁移**：不自动扫描处理存量旧图片，新功能聚焦新上传与手动编辑。
2. **视频 GPS 强制解析**：视频暂不执行复杂的二进制解析，视频若需打卡直接通过可视化地图选点器完成。
3. **多大盘创建与管理**：本次提供单一全局私密大盘（带分类/标签过滤），自定义多大盘归集列入 Phase 2。
4. **公开外链分享与加密分享**：本次严格限定仅管理员后台私有可见，列入 Phase 3。
5. **本地离线地图瓦片**：严禁内置本地瓦片，统一走 CDN 在线瓦片，避免破坏 Pages 25MB 体积红线。

## 4. 用户故事与主业务流 (Happy Path)

### 4.1 User Stories
* **Story 1 (拍照原图上传)**: 管理员在上传页选择手机拍摄的原图，前端在毫秒级内自动解析出经纬度并静默提交，上传完成后该照片自动出现在足迹大盘对应坐标上。
* **Story 2 (无坐标照片/视频手动打卡)**: 管理员上传了一张无 GPS 的单反风景照或无人机视频，在后台管理列表中点击“编辑”，弹出地图选点器，在地图上点击“杭州西湖”，系统自动填入经纬度并推测地名，管理员补上一段游记故事，保存即时生效。
* **Story 3 (足迹大盘探索与过滤)**: 管理员进入「足迹大盘」，看到全国各地的聚合气泡；在顶部选择目录 `/travel/2026/` 并勾选标签 `美食`，地图迅速聚焦并只保留符合条件的足迹点，点击后右侧滑出照片流查看图文。

## 5. 异常与边界分支表 (Edge Cases)

| 场景分支 | 触发条件 | 预期业务表现 |
| :--- | :--- | :--- |
| **无 GPS 元数据** | 上传截图、网络图或无 GPS 图片 | 经纬度置空入库，不弹报错，不在地图上展示，支持后续随时手动选点补全 |
| **视频上传** | 上传 MP4 / MOV 视频 | 不执行阻塞式深度解析，正常上传入库，GPS 留空，引导用户通过地图选点器快速标记 |
| **逆地理编码超时/失败** | 用户网络波动或第三方服务限流 | 经纬度正常保留，地名输入框保持为空或提示“请手动输入地名”，不阻断打卡保存 |
| **密集重叠点位** | 同一经纬度连续拍摄多张照片 | 点聚合插件显示数量气泡（如 `[12]`），点击散开（Spiderfy）或在右侧抽屉完整列出 12 张照片 |
| **长文本故事排版** | 故事文字超过 1000 字 | 存储与抽屉完整支持换行排版，列表卡片默认展示前 3 行并提供“展开/收起”按钮 |
